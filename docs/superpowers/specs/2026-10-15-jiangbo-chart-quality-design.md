# 江波圖放大與畫質設計（子專案 1）— 2026-10-15

## 背景與目標

2026-10-14 交易畫面改版上線後，使用者要求：「江波圖請大一點，畫質請再提升，並導入真實 K 線（已經有 API 可以抓）」。API 指富邦新一代 API（Fubon Neo API），交接包在 `Fubon_Codex_Handoff/`。該資料夾未納入版控，不得提交。

討論後確認，「江波圖」同時指中間的分時大圖和左側自選報價的小走勢。導入富邦資料的範圍很大，因此拆成三個子專案，各自走「規格→計畫→實作」：

1. **江波圖放大與畫質**（本文件）：只改畫面，用現有教材即可完成並上線。
2. **富邦每日資料管線**：每天自動抓取全部上市普通股的 1 分 K，驗證後存證。
3. **教室接上富邦教材**：學員自己挑股票，選早盤或整天，並顯示均價與成交量。

子專案 1 與 2 可以並行，子專案 3 依賴子專案 2 實測出的資料格式。

**成功的樣子**：
- 1366×900 的分時大圖高度從 539px 提高到至少 700px，1920×1080 從 719px 提高到至少 880px。
- 價格刻度以昨收為中心，不再把一兩檔的跳動畫成鋸齒；K 線不再是大塊方塊；圖上標籤不重疊。
- 左側小走勢面積約為現在的 4 倍，和大圖用同一套刻度與畫法。
- 在 1、1.25、1.5、2 倍螢幕縮放下，格線、昨收線與小走勢都維持 0% 糊邊。

## 改版前量測（2026-10-15，10/06 台積電回放到 09:27）

- 1366×900：分時圖 751×539px，下方帳務區固定 190px，圖上方有兩列資訊（開高低昨、分 K 讀數）。
- 1920×1080：分時圖 1056×719px。
- 價格範圍只保留昨收的 0.3%（`charts.tsx` 的 `span = max((high-low)*1.16, prev*0.003, …)`）。10/06 台積電因此只顯示 2574–2591，每檔 5 元的跳動約佔 100 多像素，分時線變成鋸齒，K 棒變成大塊。
- K 棒實體寬度上限為 7px。
- 圖左下角「昨」與「開／低 2575」的標籤疊在一起。
- 左側小走勢是 SVG，約 90×35px，時間軸只延伸到已揭露的分鐘。

## 已確認的決策

### 子專案 1（本文件）

1. **讓出空間的方式**：帳務區預設收成一行，可以展開；圖上方兩列資訊合成一列。
2. **分時刻度**：以昨收為中心上下對稱，上下各留「目前最高或最低離昨收的最大距離 ×1.1」，至少昨收的 ±1%。
3. **K 線刻度**：可見 60 根的高低點上下各多留 8%，並包含昨收，整個範圍至少昨收的 1.5%。
4. **小走勢**：時間軸用整段練習時間，刻度規則與大圖相同。
5. **均價線與成交量**：程式這次完成，但只在教材標明量的單位是張、而且每分鐘都有均價時才顯示。現有 Yahoo 教材不顯示。

### 子專案 2、3（之後各自寫規格，此處只記錄已定方向）

- **資料來源**：富邦歷史 1 分 K。每個交易日收盤後自動新增一天教材，正式站全班可用。行情使用授權由使用者自行向富邦確認，並將此列為上線前提。
- **抓取方式**：本機獨立的 Python 抓取程式（沿用已測通的 Python 3.13 與 SDK 2.4.0），預計放在 `tools/fubon-daily/`。
  - 由 Windows 工作排程器在週一至週五 16:45 執行，失敗時 17:30、19:00 各重試一次。
  - 輸出到 `releases` 之外的正式站資料夾（預計 `DayTradeTycoon\market-data\`），內容包括原始回應存證、整理後教材與 SHA-256 清單。先寫暫存檔再改名，清單最後更新。
  - 失敗時不寫教材，只在狀態檔記錄原因，講師頁會顯示。
  - 金鑰與憑證只留在這台電腦的本機設定，不進 Git，網站程式也碰不到。
- **股票範圍**：全部上市普通股，約一千檔，以實測為準。學員開始前可搜尋並挑選最多 5 檔，預設帶入當天成交值前 5 名。
- **時段**：學員開始時選「早盤 09:00–10:30」或「整天 09:00–13:30」。13:25–13:30 收盤集合競價沒有分 K，時間照走；這段時間送出的委託以 13:30 收盤價撮合。
- **冷門股**：沒有成交的分鐘不會有 K 棒。分時線維持原價水平延伸，K 線留空，該分鐘不撮合。
- **舊教材**：10/05、10/06 改用富邦重抓原本那 5 檔。Yahoo 原始檔保留作存證，既有練習紀錄照常可以打開。

### 富邦 API 已確認的事實（官方文件快照與交接包實測）

- **歷史 1 分 K**：`historical/candles` 的 `timeframe=1`，資料從 2023-05-23 起，每交易日 16:30 前更新。單次查詢區間須小於 1 年，限制每分鐘 60 次。
- **單位與均價**：整股的分 K `volume` 單位是張；`average` 是開盤至今的成交均價，只有分 K 提供。
- **沒有歷史逐筆**：過去的交易日最細只有 1 分 K。逐筆只能在盤中用 WebSocket 即時接收，目前只在收盤後確認過訂閱成功，還沒收過真實成交。
- **全市場快照**：`snapshot/quotes/{market}` 一次回傳全市場；`snapshot/actives/{market}` 提供成交量值排行。兩者都還沒實測，而且「平盤價 = 收盤價 − 漲跌」是推論。子專案 2 的第一步就是實測這些項目。

## 設計

### 1. 版面（桌機 ≥1200px）

- **標題列**：商品名稱、切換、分時／K 線分頁與大字現價，維持不變。
- **資訊列合一**：原本的「昨收／開盤／最高／最低」列（`td-quote-stats`）與「圖表說明＋最新分 K 開高低收＋日期」列（`td-chart-legend`）合成一列。左側放昨收、開、高、低，右側放資料說明標籤（例如「分時・分鐘收價」）與交易日期。每分鐘的開高低收讀數移到圖內左上角（見第 2、3 節）。
- **帳務區收合**：
  - 預設收成約 36px 的一行，例如「庫存 1 檔・委託 2（1 筆待成交）・成交 2・帳戶估值 9,990,584　▲展開」。有待成交委託時，「待成交」以強調色顯示。
  - 按「展開」恢復成目前 190px 的庫存／委託／成交分頁，圖跟著變矮；再按一次收起。
  - 展開按鈕帶 `aria-expanded` 與 `aria-controls`。
  - 收合狀態以 `localStorage` 記在這位使用者的瀏覽器，讀寫都包在 try/catch 中。讀不到時使用預設的收起狀態。
- **平板（768–1199px）**：使用同一套收合規則。
- **手機與長輩模式**：兩者都是單欄分頁切換（`singlePane`：分時／K 線／自選／下單／庫存），庫存本來就是獨立分頁，所以不做帳務收合。資訊列合一同樣適用，圖會跟著可用高度變大。
- **目標**：1366×900 圖高至少 700px，1920×1080 至少 880px。

### 2. 分時大圖（江波圖）

- **刻度**：以昨收為中心上下對稱。
  - 半幅 = max(已揭露最高價或最低價離昨收的最大距離 ×1.1，昨收 ×1%)。
  - 刻度範圍為 [昨收 − 半幅, 昨收 + 半幅]，右側百分比刻度因此上下對稱，例如 −1.00%／0／+1.00%。
  - 10/06 台積電（昨收 2575、高 2590、低 2575）：半幅 = max(15×1.1, 25.75) = 25.75，範圍約 2549–2601，每跳一檔約佔圖高 1/10。
- **價格線**：寬 1.5 個裝置像素，圓角轉折，維持反鋸齒（折線不做像素對齊）。水平格線、昨收線與十字線維持既有的裝置像素對齊。
- **線下填色**：維持現在的規則，以昨收線為界，高於昨收填紅、低於昨收填綠。
- **圖內讀數**：顯示在左上角，內容為時間、價格、漲跌與漲跌幅；有均價與成交量資料時，再加上「均」與「量（張）」。
  - 滑鼠移動或用方向鍵查看時，讀數跟著十字線走。
  - 平常顯示最新一分鐘。
  - 讀數區塊有半透明底色，不遮住線，也不和刻度文字重疊。
- **標籤避讓**：
  - 昨、開、高、低、前高、最新價等標籤先計算各自的矩形。
  - 兩個標籤垂直距離小於一個字高、而且水平範圍重疊時，同價位的合併成一個標籤（例如「開・低 2575」），不同價位的上下錯開。
  - 錯開後如果會超出繪圖區，改放到另一側。
- **均價線與成交量窗格**：
  - **顯示條件**：教材標明量的單位是張（例如 `catalog.volumeUnit === "lot"`），而且每根分 K 都有有效的均價（`a`）。不符合時兩者都不顯示，價格區用滿整個高度，不留空白。
  - **均價線**：黃色，寬 1 個裝置像素。
  - **成交量窗格**：位於價格區下方，約佔圖高 20%，中間隔一條格線。柱子顏色依該分鐘收盤價相對上一分鐘決定：漲紅、跌綠、平盤用中性色。
  - **型別**：`Bar` 加入選填欄位 `a`（均價）；`MorningCatalog` 加入選填欄位 `volumeUnit`。現有資料檔不需修改。

### 3. K 線

- **視窗**：維持現有的 60 分鐘視窗（`candleWindow`）。
- **刻度**：
  - 取可見 K 棒的最高、最低與昨收，上下各多留 8%。
  - 整個範圍至少昨收的 1.5%，不足時以中點為中心向兩側擴大。
  - 10/06 台積電：至少 38.6 元，範圍約 2563–2602，每跳一檔約佔圖高 13%。
- **K 棒實體**：寬度約為每分鐘欄寬的 70%，取奇數個裝置像素，讓 1 個裝置像素寬的影線正好置中；上限 13 個 CSS 像素（現在 7）。開盤價等於收盤價時，畫成 1 個裝置像素高的水平線。
- **圖內讀數**：左上角顯示時間、開、高、低、收與漲跌，跟著十字線走；有資料時再加上「量（張）」。
- **成交量窗格**：顯示條件與畫法同第 2 節。

### 4. 左側自選小走勢

- **每檔排成兩層**：
  - 上層：股名與代號；右側放現價、漲跌與漲跌幅。
  - 下層：小走勢佔滿整列寬度，高 56px（長輩模式 64px）。
  - 尺寸約為：1366 寬時 260×56，1920 寬時 380×56。
- **高度預算**：在 1366×900 下，5 檔（每檔約 118px）加上標題列與下方作戰計畫，放得進左欄（832px）。手機與長輩模式的「自選」分頁是單欄，可以捲動。
- **刻度與時間軸**：時間軸為整段練習時間（`startT` 到教材結束）；刻度用第 2 節的對稱規則（至少 ±1%）。因此小圖和大圖形狀一致。
- **畫法**：從 SVG 改成 canvas，與大圖共用同一組繪圖規則。
  - 昨收虛線對齊像素，虛線長度以裝置像素計算。
  - 價格線寬 1.5 個裝置像素，線下紅綠填色。
  - 最新價畫一個實心點。
  - 缺分鐘的地方斷線，大圖與小圖都沿用現行規則。富邦冷門股「沒成交的分鐘」改為水平延伸，由子專案 3 處理；這需要教材區分「沒成交」與「資料缺漏」。
- **無障礙**：canvas 標 `aria-hidden`；股價文字仍在列表中可讀。
- **手機**：「自選」分頁使用同一個元件，小走勢跟著加寬。

### 5. 程式結構

- **純計算函式**：放在 `src/lib/market/chart-data.ts`，各自有單元測試。
  - `jiangboPriceRange(prev, high, low)`：分時刻度。
  - `candlePriceRange(bars, prev)`：K 線刻度。
  - `candleBodyWidth(columnCssPx, deviceRatio)`：回傳 CSS 像素寬度，換算成裝置像素是奇數，上限 13 CSS 像素。
  - `resolveChartLabels(labels, bounds)`：標籤的合併與錯開。
  - `showVolumeAndAverage(catalog, bars)`：均價與成交量的顯示判斷。
- **帳務摘要**：新增 `src/lib/morning-ledger.ts`，其中 `ledgerSummary(session)` 計算庫存檔數、委託數、待成交數與成交數，並附 `morning-ledger.test.ts`。
- **小走勢**：繪圖與大圖共用像素對齊工具（`snapEdge`、`hairlineDevicePixels`、裝置像素虛線），不複製一套。

## 測試與驗收

1. **單元測試先行**：第 5 節的函式先寫失敗的測試再實作。至少涵蓋：
   - 分時刻度上下對稱、至少 ±1%，以及 10/06 台積電的實際數值。
   - K 線範圍至少 1.5%，並且包含昨收。
   - 實體寬度在 1、1.25、1.5、2 倍縮放下都是奇數個裝置像素，而且不超過上限。
   - 同價標籤會合併、相近標籤會錯開、不會超出繪圖區。
   - 待成交筆數的計算。
   - 均價或單位缺漏時不顯示均價與成交量。
2. **既有檢查全部通過**：`npm test`、`npm run typecheck`、`npx eslint src --quiet`。
3. **版面檢查**（`desk-layout.mjs --strict`，8 種尺寸加長輩模式）：
   - 1366×900 圖高至少 700px，1920×1080 至少 880px。
   - 帳務區預設收起，按下後展開，`aria-expanded` 隨之改變。
   - 桌機小走勢至少 200×48px。
   - 既有項目維持：無小於 11px 的文字、無水平溢出、桌機整頁不捲動、手機點擊區至少 44px、下單按鈕可見。
4. **銳利度**：在 1、1.25、1.5、2 倍縮放下，大圖與小走勢的格線、昨收線遮罩檢查都是 0% 糊邊。
5. **下單流程**（`desk-orders.mjs`）：市價買、閃電賣與刪單、沒有庫存時賣出，全部通過。腳本會先展開帳務再核對內容。
6. **均價與成交量**：用富邦文件中的分 K 範例格式做測試資料，確認符合條件時顯示、不符合時不顯示。真實資料的視覺驗收留到子專案 3。
7. **截圖對照**：1366×900 與 1920×1080 的改前、改後截圖，交給使用者確認。
8. **上線**：完成後只提交。推送與部署正式站等使用者指示，流程依 `docs/deployment-2026-10-12.md`，並在正式站登入驗收。

## 風險

- **帳務收起後看不到委託明細**：摘要列會顯示待成交筆數並以強調色提醒，成交快訊照常出現在提示列。如果學員回饋不夠清楚，再改成「有待成交時自動展開」。
- **±1% 下限讓平靜的日子顯得平緩**：這是刻意的取捨，起伏的大小反映真實幅度。
- **整段時間軸讓開盤初期的小走勢很短**：子專案 3 選「整天」時，09:30 的線只佔 1/9 寬度。已接受，因為這樣小圖和大圖的時間對得上。
- **均價與成交量在子專案 3 之前沒有真實資料可以驗收**：先用格式相同的測試資料驗證，子專案 3 再補真實畫面驗收。
- **平板版面**：820px 寬的分頁與收合列之間的互動，需要在版面檢查中逐一確認。
