# 紀律等級、稱號與慶祝設計（好玩計畫 子專案 C）— 2026-10-18

## 為什麼要做

子專案 A 讓新學員第一次就上手，B 給了每天一個很小的練習習慣（每日一題、連續天數、本週完成）。C 要讓學員**看得到自己的進步**：每次照紀律完成練習，就累積分數、升等級、拿稱號與徽章，完成時有一點慶祝感。學員裡有很多長輩，主要用手機。

使用者在子專案 A 已定的方向（`docs/superpowers/specs/2026-10-16-easy-start-design.md`「後續子專案已定方向」）：
- 計分以紀律為主：作答、設停損、說出理由就拿主要分數；判讀正確另外加「眼力」分。猜錯但有停損，分數比猜對但沒停損高。
- 練習與每日一題都計分，累積等級、稱號與徽章。
- 完成時有動畫、音效與鼓勵；尊重「減少動態效果」，音效可以關。

2026-10-18 使用者說「做起來」，不先回答問題。以下凡標 **（設計決定）** 的，都是設計者的判斷，不是使用者的指定。

## 目標、非目標、反目標

**目標**
- 學員每完成一題、一輪練習，立刻看到「這次拿到幾分、為什麼」，以及離下一級還差多少。
- 升級、拿到徽章時有短短的慶祝：動畫、可選的音效、一句鼓勵，朗讀開啟時唸出來。
- 大廳看得到目前等級與稱號；有一頁說清楚怎麼得分、拿過哪些徽章。
- 計分規則公開、簡單，長輩看得懂。

**非目標**（之後再做）
- 講師頁顯示學員等級。
- 排行榜、班級比較。
- 用分數兌換任何東西、連續天數保護卡。
- 推播或 LINE 通知。

**反目標**（就算功能都對，出現這些也算失敗）
- 賺越多分數越高，或任何和損益掛鉤的分數。
- 扣分、降級、分數歸零；斷一天就失去已有的東西。
- 讓學員覺得「答錯」被懲罰：不顯示「眼力 0 分」「答錯」。
- 學員看到其他同學的分數或名次。
- 慶祝擋住下一步（全螢幕彈窗要按掉才能繼續）、播很久的動畫、沒問過就發出聲音。
- 重複練同一課就能刷分。

## 現況（2026-10-18 調查）

- **每日一題**：`daily_answers` 記錄 `choice`（enter／watch／skip）、`stop_price`（進場才有，必填）、`reason`（四個標籤之一或空）。題目 `daily_questions.payload` 有 `level` 與 `outcome`；`src/lib/daily/reveal.ts` 的 `brokeOut()`（未匯出）判斷有沒有做出後高，揭曉的「這題要學的」依 yes／faded／held／no 四種情況選句子。連續天數與本週天數每次請求即時計算（`daily/progress.ts`）。
- **模擬練習**：`morning_sessions.state_json` 存計畫（`focusCode`、方向、理由、進場、失效條件）、委託、成交、庫存、`reflection`（復盤，完成時必填）與 `completed`。`created_at` 在訪客轉正式帳號時不變；`updated_at` 會被重設，不可靠。沒有停損單。只有兩個固定課程，可以無限次重練。
- **完成畫面**：`morning-practice.tsx` 的 `Completion` 顯示「這是操作足跡，不是獲利能力評分」與三個勾選；其中「先觀察，再決定是否操作」的判斷永遠成立（委託至少在 cursor 1 送出），是既有小錯。
- **訪客轉正式帳號**：`linkGuestRecords` 會搬 `daily_answers` 與 `morning_sessions`。
- **聲音**：只有已停用舊畫面的 `src/lib/game/audio.ts`（方波嗶聲、開關不保存）。偏好設定在 `src/lib/display-preferences.ts`（標準／大字、朗讀提示），存在裝置上。
- **沒有任何**等級、稱號、徽章、分數的資料或畫面。

## 設計

### 1. 分數從既有紀錄即時算出（設計決定）

- 不新增資料表，也不新增遷移。每次需要時，從 `daily_answers`（含題目的 `level`、`outcome`）與已完成的 `morning_sessions` 算出總分、等級、徽章。
- 好處：
  - 已經做過的每日一題與練習，上線當天就算進去。
  - 訪客轉正式帳號時，紀錄搬過去，分數自然跟著走，不必改 `linkGuestRecords`。
  - 調整規則時不必搬資料；也不會因為重送請求而重複加分。
- 代價：規則改了，舊分數也跟著改。所以規則只加不減；真的要改，寫在發布紀錄裡。
- 計算是純函式（`src/lib/discipline/`），伺服器端只負責讀資料。讀題目時只取 `payload->'level'` 與 `payload->'outcome'`，不讀整天的 K 棒。

### 2. 計分規則（設計決定）

分兩種：**紀律分**（主要）與**眼力分**（加分）。總分 = 紀律分 + 眼力分。

**每日一題**（每題只能答一次，自然不能刷）

| 項目 | 分數 | 條件 |
|---|---|---|
| 完成作答 | 紀律 +10 | 答了這一題 |
| 說出理由 | 紀律 +5 | 選了一個理由標籤 |
| 眼力 | 眼力 +3 | 判讀和後來的走勢一致（見下） |

- 進場一定要設停損（B 已強制），所以「猜對但沒停損」不會發生。
- 「猜錯但有理由」15 分 > 「猜對沒理由」13 分：紀律永遠比眼力重。
- **眼力怎麼算**：和揭曉的「這題要學的」一致。
  - 做出後高（含「突破後收盤又跌回」）：選「進場」算一致。
  - 沒有做出後高：選「觀望」或「不追」算一致。
  - 題目是五五波挑的，每次都選同一個答案，眼力分大約只拿一半。

**模擬練習**（每個台北日期最多算一輪）

| 項目 | 分數 | 條件 |
|---|---|---|
| 完成一輪並復盤 | 紀律 +15 | 這一輪按了完成並留下復盤 |
| 照計畫的股票 | 紀律 +5 | 所有委託都下在計畫寫的那檔股票（沒下單也算） |
| 收盤前不留倉 | 紀律 +5 | 完成時沒有剩餘庫存（沒下單也算） |

- 練習日 = 這一輪 `created_at` 的台北日期。同一天完成好幾輪，只算分數最高的那一輪。再練一輪是為了自己，不會多拿分。
- 「沒下單也算」：條件沒成立就不做，本來就是紀律。
- 練習不給眼力分：練習的結果就是損益，不拿來計分。
- 一天最多：每日一題 18 + 練習 25 = 43 分。

### 3. 等級與稱號（設計決定）

分數只會增加，等級不會掉。稱號都在講紀律與判讀，不用「賺」「股神」「大富翁」這類字。

| 等級 | 稱號 | 需要總分 |
|---|---|---|
| Lv1 | 新手學員 | 0 |
| Lv2 | 準時報到 | 25 |
| Lv3 | 有計畫 | 80 |
| Lv4 | 停損守門員 | 160 |
| Lv5 | 紀律學員 | 280 |
| Lv6 | 穩健操盤 | 450 |
| Lv7 | 冷靜判讀 | 680 |
| Lv8 | 紀律高手 | 980 |
| Lv9 | 盤感老手 | 1350 |
| Lv10 | 紀律大師 | 1800 |

- 第一天同時做每日一題（至少 10）與一輪練習（至少 15）就到 Lv2，第一天就有升級的感覺。
- 每天都做完兩樣（約一週 200 分），大約十週到 Lv10；只做每日一題，大約半年。
- Lv10 之後分數照樣累積，畫面寫「已是最高等級」。

### 4. 徽章（設計決定）

八個，全部從紀錄算出，條件寫在徽章頁上：

| 徽章 | 條件 |
|---|---|
| 第一題 | 第一次完成每日一題 |
| 第一輪 | 第一次完成模擬練習並復盤 |
| 連續 5 天 | 每日一題曾經連續 5 題（規則同 B 的連續天數，沒發題的日子不中斷） |
| 全勤一週 | 某一週（週一到週五，以發題日計）發出的題全部答完，而且那週發了 5 題，或那週已經過完 |
| 說出理由 10 次 | 10 題有選理由 |
| 練習 5 天 | 在 5 個不同的台北日期完成練習 |
| 每日一題 20 題 | 答滿 20 題 |
| 練習 20 天 | 在 20 個不同的台北日期完成練習 |

- 拿到就永遠保留。
- 不做和運氣有關的徽章（例如「停損被觸發」「連續猜中」）。

### 5. 慶祝（設計決定）

**什麼時候出現**：每日一題送出後的揭曉頁、練習按下完成後的完成畫面。用同一個「紀律分」卡片元件。

**卡片內容**，由上而下：
1. 「這次拿到 +18 分」，下面一行一個項目：「完成作答 +10」「說出理由 +5」「眼力：判讀和走勢一致 +3」。只列拿到的項目，不列沒拿到的。
2. 等級列：「Lv3 有計畫」與進度條「再 42 分升到 Lv4 停損守門員」。進度條從這次之前的位置長到現在的位置。
3. 升級時：卡片上方多一個大字橫幅「升級！Lv4 停損守門員」，一句鼓勵（依等級固定句子，例如「每一筆都先想好停損，這就是守門員。」）。
4. 拿到新徽章時：徽章以小動畫出現，下面寫條件。
5. 同一天的練習分已經拿過時，不顯示「+0」，改寫：「今天的練習分已經算過了，再練一輪是為了自己。」
6. 一行小字：「分數只看練習習慣與紀律，不看賺賠。」連結到「我的紀律」頁。

**動畫**：
- 只用 CSS：分數數字淡入、進度條長出來（約 0.8 秒）、升級橫幅與徽章有一次光暈與小星點（約 1.2 秒）。不閃爍，不重複播放。
- 「減少動態效果」開啟時，全部直接顯示最終狀態。
- 卡片在頁面內，不是彈窗；下一步的按鈕照常可以按。

**音效**：
- 預設關閉。課堂上大家的手機同時響會干擾，長輩也不喜歡突然有聲音。
- 開關三處：大廳頁首「標準｜大字」旁邊（和朗讀提示放一起；手機寬度不放，避免頁首多一行）、慶祝卡片上、「我的紀律」等級卡。存在裝置上。
- 用 Web Audio 合成柔和的正弦波：拿分是兩個音，升級是四個音的上行琶音，總長不超過一秒。不另外放音檔。
- 只在學員按下送出／完成之後播放（瀏覽器規定要有點擊）。

**朗讀**：朗讀開啟時，揭曉或完成後唸「拿到 18 分」；升級時再唸「升級了，第 4 級，停損守門員」。

**螢幕報讀**：分數與升級訊息放在 `aria-live="polite"`。

### 6. 大廳與「我的紀律」頁（設計決定）

**大廳的等級列**
- 放在「今天三件事」下面：每日一題與今天三件事仍是手機第一個畫面。
- 一列：等級徽記「Lv3」、稱號、細進度條、「再 42 分升級」、已拿到的徽章數「徽章 3／8」。整列可以點，進「我的紀律」。
- 離線包不顯示（和每日一題卡片一樣）。

**「我的紀律」頁 `/progress`**
- 手機優先的單欄頁，和每日一題同一套深色主題。
- 由上而下：
  1. 頁首：返回大廳、標題「我的紀律」、「標準｜大字」切換。
  2. 等級卡：等級、稱號、總分（紀律分與眼力分分開列）、進度條、下一級稱號。
  3. 「怎麼得分」：第 2 節的兩張表，用白話寫。
  4. 徽章：八格。拿到的上色並寫取得日期；沒拿到的灰色，寫條件與目前進度（例如「說出理由 6／10」）。
  5. 最近得分：最近 10 筆，例如「10/19 每日一題 +15」「10/19 模擬練習 +25」。
  6. 等級表：十個等級與稱號，目前所在那一級標出來。

### 7. 介面（設計決定）

- **純函式** `src/lib/discipline/`：
  - 輸入：每日一題作答紀錄（題目 ID、發題日、選擇、有沒有理由、有沒有做出後高）、已完成練習紀錄（練習日、有沒有復盤、委託股票、計畫股票、完成時庫存）、已發題日清單、現在時間。
  - 輸出：總分、紀律分、眼力分、等級、八個徽章（有沒有拿到、取得日期、進度）、最近得分。
  - 慶祝 = 「含這次」與「不含這次」兩份結果的差：拿到的項目、之前與之後的等級、新徽章。不需要存「看過了沒」。
- **`GET /api/discipline`**：和 `/api/daily` 相同的保護（入場碼、同源檢查、頻率上限、需要登入或訪客）。回傳上面的摘要。
- **每日一題 `POST /api/daily`**：真的寫入作答時，回應多一個 `celebration`；重送同一題回傳原答案，`celebration` 為空。
- **練習 `POST /api/morning` 的 `finish`**：這一輪真的完成時，回應多一個 `celebration`；用同一個操作編號重送時為空。
- `brokeOut()` 改成從 `reveal.ts` 匯出，讓計分和揭曉用同一個判斷。
- 順手修正：`Completion` 的「先觀察，再決定是否操作」改成和計分一致的條件，避免永遠成立。改成「照計畫的股票操作」「收盤前不留倉」兩項，只在成立時顯示。

### 8. 長輩與手機的驗收標準

沿用子專案 A、B：
- **版面**：手機 375、320，平板 820，桌機 1366，大字模式 375 與 1366：大廳等級列、`/progress`、兩個慶祝卡片都沒有水平溢出或文字被截斷。
- **按鈕**：手機與平板至少 44px；大字模式至少 56px。
- **文字**：至少 11px；大字模式說明文字至少 15px。對比至少 4.5:1。
- **減少動態效果**：沒有動畫。
- **音效**：預設不出聲；開了才響。
- 每日一題在 375×812 第一個畫面就能作答的要求不受影響（慶祝卡片在揭曉內容下方）。

## 測試與驗收

1. **純函式單元測試**：每一條計分規則、每日上限、取當天最高的一輪、十個等級的門檻、八個徽章（含全勤一週的「那週已過完」條件、連續 5 天跨過沒發題的平日）、慶祝差異（升級、新徽章、同日第二輪不加分）。
2. **伺服器測試（PGlite）**：從真實資料表讀出分數；訪客轉正式帳號後分數跟著走；每日一題重送不重複慶祝；練習 `finish` 重送不重複慶祝。
3. **畫面檢查**：新的 `scripts/qa/desk-discipline.mjs` 走完「訪客 → 每日一題 → 揭曉看到 +分與 Lv2 → 練習完成看到慶祝 → 大廳等級列 → `/progress`」，各尺寸檢查溢出、字級、按鈕大小、對比；減少動態效果時沒有動畫；預設不出聲。
4. 既有的 `desk-premium`、`desk-layout --strict`、`desk-daily`、`desk-guest`、`desk-states`、`desk-orders` 照樣通過。
5. **上線**：沒有遷移。照既有流程停機、備份、部署。部署前先問使用者。

## 風險

- **規則改了，舊分數跟著變**：因為是即時計算。規則只加不減，改動要寫進發布紀錄。
- **分數算得太慢**：每次請求讀一個人的全部作答與練習。一個人一年最多幾百筆，只讀需要的 JSON 欄位，問題不大；以後真的慢再加快取表。
- **練習日以開始時間算**：晚上開始、隔天早上才完成的一輪，算在開始那天。
- **眼力的定義**：「突破後收盤又跌回」算做出後高，選進場算一致。這和揭曉頁的說法一致，但有人會覺得那天進場「其實是錯的」。眼力只有 3 分，影響很小。
