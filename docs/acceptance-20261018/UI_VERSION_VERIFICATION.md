## 2. GitHub 與正式站：程式碼相同，CSS 不同

不能寫成「正式站和 GitHub 完全相同」。實際情況分三點：
- 程式行為相同。
- CSS 不同。
- 正式站無法從乾淨的 clone 逐位元組重現。

**比較方式**
- 05:08Z 建立乾淨的 detached worktree（`.worktrees/verify-clean`，HEAD `d4b45403`），重新安裝與建置：`npm ci`、`npm run build`，05:19:48Z 完成。環境：Node v24.15.0、Vite 8.1.5、Tailwind 4.3.3。
- 用 `qa/acceptance/compare_builds.mjs` 逐檔比對建置結果與正式站 release。
- 原始差異清單全部保留：
  - `docs/acceptance-20261018/evidence/build-compare-public.txt`
  - `docs/acceptance-20261018/evidence/build-compare-server.txt`

**正規化規則**（只用在第 2、3 輪，第 1 輪是原始比對）
- 第 2 輪：內容雜湊檔名 `<名稱>-<8 個 [A-Za-z0-9_-] 字元>.<js|css|mjs>` 改寫成 `<名稱>-[hash].<副檔名>`，路徑與文字檔內容都套用。換行字元另外比較（CRLF → LF）。
- 第 3 輪：只處理仍然不同的檔案，處理以下建置資訊：
  - 兩邊檔名裡出現過的雜湊字串（包括打包器把 `-` 換成 `_` 後的識別名稱）；
  - 字串常數裡的 `\r\n`；
  - 建置所在的絕對路徑；
  - 檔案 mtime；
  - Nitro 延遲載入處理器的自動名稱；
  - 公開資產表的排列順序。

| 範圍 | 第 1 輪：原始比對 | 第 2 輪：雜湊檔名正規化 | 第 3 輪：建置資訊正規化 |
|---|---|---|---|
| `public/`（189 個檔） | 位元組相同 172；同路徑不同 1；只在一邊各 16 | 相同 187（其中 15 個只差雜湊檔名）；只差換行 1（`sw.js`）；仍不同 1 | 仍不同：只有 `styles-*.css` |
| `server/`（133 個檔） | 位元組相同 111；同路徑不同 2；只在一邊各 20 | 相同 130（其中 19 個只差雜湊檔名）；仍不同 3 | 3 個都只差建置資訊（見下） |

**server/ 那 3 個檔的差異**
- `index.mjs`：公開資產表的順序不同。另有 17 筆資產紀錄不同，對應的正是 public 裡大小或內容不同的 17 個檔：CSS、`sw.js`、15 個引用 CSS 檔名的 JS。延遲處理器的名稱也不同。
- `_ssr/db-*.mjs`：內嵌的 SQL 換行，乾淨 checkout 是 CRLF，正式站是 LF。
- `_tanstack-start-manifest_v-*.mjs`：記錄的建置絕對路徑不同。

**CSS 的差異與原因**
- 正式站的 `styles-CXm3MunE.css` 比乾淨建置多 280 個選擇器（2,277 比 1,997）、多 362 個區塊，多約 26.8 KB。
- 反過來，乾淨建置有的選擇器，正式站全部都有（只在乾淨建置的 0 個）。完整清單在 `build-compare-public.txt` 的 `CSS-ONLY-release` 行。
- 原因：正式站是在主工作區建置的，那裡有一個未追蹤的資料夾 `當沖大富翁-地端/`，Tailwind v4 會掃描所有沒被忽略的檔案找 class 名稱。
- 03:11Z 第一次比對時寫的「327 條規則」是另一種計數法；以這次可重跑的計數為準。

**影響**：在本次測過的畫面上（學生旅程 L01–期末、作者擷取的 88 張圖、數位版與 PDF 的檢查）沒有看到影響。沒有測過的畫面，不能據此宣稱沒有影響。
**本輪處理**：照使用者指示，不為了消除這個差異重新部署正式站。建議下次部署時改在乾淨的 worktree 建置，或把該資料夾加入 `.gitignore`。
