# 早盤分鐘 K 原始資料一致性稽核

2026-10-06。這份檢查直接對照保留的 Yahoo 原始回應，不只比對研究補充包與網站產物。

## 已核對結果

`server/data/morning-2026-10-06.json` 的 2330、2317、2454、2382、2308，各 90 根，共 450 根分鐘 K，與 `research/daily-market/2026-10-06-collection/intraday/raw/yahoo-<代號>-7d-1m.response` 的 `timestamp` 及 `indicators.quote[0]` 一一相同。

- 比對 1,800 個 O/H/L/C 價格、450 個時間與 450 個來源量值，差異為 0；五份原始回應的 SHA-256 同時符合當初 request 紀錄及 replay manifest。
- 來源為 `Asia/Taipei`、UTC+8、`1m`。分鐘起點自 09:00 至 10:29，間隔均為 60 秒；網站 `t` 為距 09:00 的秒數，範圍 0～5340。
- 09:00 那根完整 OHLC 要到重播 09:01 才顯示；10:29 那根要到 10:30 才顯示。原始時間沒有改標成分鐘結束時間。
- 產物直接保留原始 O/H/L/C，沒有改用 adjusted close、呼叫 `roundToTick`、套大盤投影或對 OHLC 內插。原始資料缺值時檢查會失敗，不會補造 K 線。

保留的 TWSE 日資料只旁證「09:00 開盤值比較」與「分鐘價格落在全日日高低區間內」。目前五檔開盤比較相同、價格均在日區間內；這**不等於官方逐分鐘驗真**，也不能驗證逐筆先後、分鐘成交量或實際撮合。

每檔 09:00 來源量均為 0，量的完整性與單位仍未獨立核實。網站不以日成交量回填、不顯示量柱／VWAP，也不把分鐘 OHLC 合成為逐筆路徑。這份稽核證明網站產物忠實保留既有 Yahoo 來源，不宣稱第三方原始資料等於交易所逐筆真值。

## 可重複執行

```powershell
node scripts/verify-morning-source.mjs
node --test scripts/verify-morning-source.test.mjs
```

檢查不連網、不修改來源或網站產物。負向測試在記憶體中移動時間、移除分鐘、改動各 OHLC、填補來源量、製造缺值及換錯股票；以上都必須被拒絕。額外放入 adjusted-close 陣列不會影響比對，因為基準只使用原始 `quote` 欄位。

既有 `prepare-morning-data.mjs --check` 仍負責完整產物與研究證據的重建一致性；`verify-morning-build.mjs` 負責完整未來資料不可流入公開／離線產物；HTTP 驗收負責登入、owner、游標與重啟保存。這三類檢查與原始 OHLC 比對各自回答不同問題。

## 舊版江波與進入路徑

舊首頁 `AppShell → Lobby → beginLesson → useGame.start → DayMarket` 仍會進入教學生成盤。`real-paths.ts` 的 `projectStock` 把個股全日日 O/H/L/C 縮放到大盤五秒節奏，尾段混合到日收盤價，再取樣聚合成分鐘 K；量與五檔亦為模擬。舊「江波」與「K 線」按鈕共用這個來源，與 `/morning` 的真實來源分鐘資料不同。

新 `/morning → /api/morning → morning-data.server` 使用上述 450 根來源分鐘 K；圖表只收到目前游標已完成的前綴。稽核前，新頁雖預設分鐘 K，但舊首頁主要「開始第一課」先啟動生成盤，而真實早盤入口位於後方，容易讓使用者繼續看到生成 K。

本次將線上首頁主動作改接 `/morning`，舊桌機與手機 K 選項改名「合成 K」，並在原圖上方明示來源與真實 K 入口。切換會暫停原盤並解除閃電模式，不結算、不修改庫存與委託；離線模式不提供伺服器路由。沒有把另一日期的真實分鐘 K 塞入舊 `DayMarket`，以免價格與撮合時間不一致。

## 繪圖修正與驗收

- 真實完成分鐘模式再次限制 `t + 60 <= 已揭露時間`。K 棒置於自己的分鐘區間中央，修正首根被裁切；開收相同用水平十字線。
- 分鐘收價線改在區間結束時間標點，提示完整區間；例如 09:00 分鐘的收價標在 09:01，而非 09:00。資料本身的 `t` 仍保持原始分鐘起點。缺分鐘不跨接線，也不新增合成的當前價尾點。
- 每根來源 OHLC 保持原值。頁面新增最新完整 K 棒讀值及已揭露分鐘表格，可在手機內部橫向捲動核對；不帶出未來分鐘。
- 全套回歸 519 通過、0 失敗；1 項需指定候選的 HTTP 測試另對 release `20261006T123326963Z` 通過。型別、相關 ESLint、离線及正式 build、來源直比與公開產物防洩漏檢查通過。
- 同一候選在外部 Chrome 的 320/375/820/1366 視窗驗收，頁面無橫向溢出。長輩文字 22px、主操作至少 63px 高；此為視窗響應式測試，非實體 iPad 測試。
- 實際操作確認第一根 K 的完整圖形、15 根來源明細、收價區間讀值、切換鴻海仍共用游標、桌機與手機合成標示；原盤從運行切到真實 K 後，返回保持 09:00:02 暫停。正式學員紀錄未拿來測試。
- Chrome 有既有擴充套件 storage context 錯誤（另有相同文字的頁面 URL 紀錄），不宣稱主控台零錯誤；本次頁面與上述操作可完成。
